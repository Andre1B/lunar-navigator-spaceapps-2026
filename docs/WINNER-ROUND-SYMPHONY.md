### Runtime walkthrough (2026-11-15, own browser tab)

The actual Vercel site was opened in a dedicated tab after the coordinator released the QA browser/GPU. This paragraph records actions and visible responses, not a complete accessibility or device QA. The tab was closed after this pass and the coordinator was notified.

- **Start and introduction — observed.** `TAP TO START` advanced to `October, 2024`; successive arrow controls revealed the JWST launch paragraph and then “Let's explore the stars and find some of these melodies.” The next arrow opened `/menu`. No console errors or warnings were captured. The title screen is a visual prompt, not a semantic button.
- **Menu — partial / blocked by input surface.** The menu displayed “EXPLORE THE STARS”, three star nodes, and progress. After completing Cosmic Cliffs, it showed 33% and a check mark on that node; another star displayed “START ADVENTURE.” The chapter nodes are drawn in a canvas. The DOM had no anchors, buttons, or focusable controls, and I could not select the next node through the available browser interaction surface. I opened the observed `/sagittarius` and `/crab` routes directly; this does not verify menu navigation to them.
- **Cosmic Cliffs — observed route and sequence.** The route opened on a Hubble scene with chapter number/title and “CLICK TO CONTINUE.” Clicks revealed an introduction, the Hubble/NGC 3324 description, then the full-screen Hubble/Webb image comparison with a 50% divider and `NEXT ADVENTURE`. Clicking the semantic button returned to `/menu` and advanced progress to 33%. A browser drag attempt on the divider left it at 50%; this result is inconclusive about product behavior because the browser harness does not expose pointer coordinates for the drag target. The displayed instruction says to sweep the mouse; touch/keyboard alternatives were not established.
- **Sagittarius C — observed route and controls.** After a user click, an audio element began playing (it was paused at time zero on route load). The narrative described the dense Milky Way center and a 50-light-year portrait, then asked for an estimate of the stars in the image. The numeric control began at `5`; one decrement click left it at `5`, while one increment click changed it to `50`. `GUESS` returned “Close one!” and said the image was estimated at about 500,000 stars. The exact mapping between the displayed number and exponent, and whether the first decrement was ignored or bounded, remain unclear. The three controls were rendered as buttons; I did not complete a keyboard activation check.
- **Crab Nebula — observed route and controls.** After a user click, its audio element began playing (paused at route load). The story described the 1054 supernova, then JWST NIRCam/MIRI, followed by explanatory text for dust, doubly ionized sulfur and synchrotron. Each of the three semantic buttons highlighted with a matching color and outline; the visual layer also changed color. The buttons did not expose `aria-pressed` in the inspected DOM. No mute, volume or pause control was visible. I did not complete a keyboard activation check.
- **Motion and sound — observed / limited.** The full-screen images and text transitioned through fades/blur; the screenshots show the effects, but timing was not measured. Audio started after interaction on both chapter routes in this browser session; volume remained 1 and no player controls were visible. This differs from the static bundle's attempted mount-time playback and is the runtime result to cite for this session.
- **Keyboard, mobile, reduced motion — status.** Menu and title/intro states exposed no semantic focusable controls. A narrow 474 x 1023 CSS-pixel viewport had no document overflow on Crab, but its title screen did not advance in my attempted clicks; the exact 390 x 844 viewport could not be set because the browser rejected it at the current zoom. Treat small-screen navigation as unverified, not as a confirmed product defect. Reduced-motion preference was not emulated or tested.
- **Sources, credits and version.** I found no visible source/asset-credit UI during the screens reviewed. Framework source suggests Next.js, but there is no linked repository, project license or exact Space Apps submission build identified in the checked pages. NASA imagery licensing/provenance is therefore not inferred from the fact the images are displayed.

## Universe Symphony — static route/source checkpoint

Direct GETs returned HTTP 200 for `/`, `/menu`, `/cliff`, `/sagittarius`, and `/crab`. Each is a client-rendered route with a page-specific JS chunk. This establishes published route responses, not that any route renders or works at runtime. I read only the small app/menu/chapter chunks as text; no code was executed.

- The home bundle stores `stage=0`; runtime showed a start screen, then three click-advanced content screens (October 2024, a JWST paragraph, and an invitation to explore), then `/menu`. The static source had been misread as four post-start cards; runtime corrects that count. The click-to-menu transition worked; whether the timing is understandable remains untested.
- The menu bundle contains three named nodes: Cosmic Cliffs, Sagittarius C and Crab Nebula. It shows “EXPLORE THE STARS” before a chapter has been selected and a completion percentage. A pointer tap on the current star navigates to its chapter. A 43 s timer and later retry/completion states exist in source. Whether the 43 s state or progress model appears as intended remains unverified.
- Cosmic Cliffs copy calls for sweeping the mouse over an image to reveal JWST details over Hubble's NGC 3324 image. Its source contains mouse and touch handlers for a 50/50 comparison slider, plus a particle backdrop. It also declares an optional autoplay mode, disabled in the inspected component. A mouse-only instruction is a likely mobile/keyboard mismatch, pending runtime checks.
- The Crab Nebula text describes the 1054 supernova and identifies NIRCam/MIRI, dust, ionized sulfur and synchrotron as image components. Three labels are present in the source. How selections map to image layers and any source credits have not been checked visually.
- The Sagittarius component includes an audio element and an exponent control `5 * 10^f`, plus correct/error text. Exact meaning of the exponent, usable range, chapter task and feedback remain unresolved from the short text inspection.
- A `piano_nasa.wav` loop is requested on home mount before an interaction; other tracks are added for menu/chapter/hover states. This is a code-level autoplay attempt, not evidence a browser played sound. No volume, mute, pause or user gesture was verified.
- Source describes 800 starfield items and implements word/arrow opacity/blur fades. Word reveal defaults to 0.5 s with a 0.05 s stagger; chapter text fades after a 2 s delay using 1.5 s and 4.5 s transitions; arrow bounce duration is 1 s. These values are read from compiled bundles, not timing measured from the display. Exact animation package and reduced-motion/responsive behavior remain unverified.
- Framework evidence is Next.js App Router assets and React chunks. The project has no identified repository URL, package manifest, root license, data/citation page or asset-credit record from the pages inspected. This is a bounded search, not proof none exists elsewhere.

**Lunar comparison (inference).** A route-by-route story can make an abstract subject approachable, but only if each action is self-explanatory and tied to a source-backed result. Symphony runtime showed readable chapter copy and visible layer feedback, while menu navigation was canvas-only and keyboard operation was not established. Lunar already names the delayed-arrival problem and connects comparison, learning and exploration. No novice comprehension study has been run for Lunar, so first-time understanding remains an evidence gap. Symphony's sound and visuals were observed; visitor comprehension was not tested.

### 1. Astro Sweepers — Galactic Impact (2025)

**What I checked.** The live team-branded site at [astro-sweepers.vercel.app/home](https://astro-sweepers.vercel.app/home) and four server-rendered routes: `/home`, `/solution`, `/pricing`, `/sustainability`, `/about`. The top navigation leads to `/solution`, `/pricing`, `/sustainability`, `/about`, `/contact`. The `/problem` route linked from the footer currently returns HTTP 404. No contact form was submitted.

**Observed in page content.** Home opens with “Saving Space, One Satellite at a Time” and a “See How It Works” action to Solution. Solution separates what it labels **Live Today**, **In Development**, and **Future Vision**. Pricing shows service tiers, a Monthly/Yearly toggle and “Demo Country Report,” “Request a Demo” and “Talk to Sales” actions. Sustainability presents a proposed “LEO Accord.” About introduces a six-person team. Footer includes Privacy Policy, Terms of Service, generic social links and a generic `github.com` link, not a project repository. Commercial pricing detail is not relevant to Lunar's research tool.

**Claims, not independently checked.** Home advertises 9,000+ active satellites, 1M+ debris and 99.8% collision-prediction accuracy. Solution describes NASA DAS, Space-Track and SPARK inputs, ASRI, AI scoring and future ML models. The home copy explicitly says the project is not affiliated with NASA and describes alignment with DAS. This is the team's current marketing site; its identity as the exact judging-weekend demo and the availability of the operational dashboard are unverified. No linked source repository or project license was identified; the tech stack is not confirmed by a readable package manifest.

**Against Lunar.** The useful design distinction is “available now / in development / future,” especially for a model-driven tool. Lunar already states its computed time coverage and separates modeled visibility from claims about power or communications. It does not need an ASRI-style composite score. A newcomer check could verify whether today's calculation and its limits are clear; no such comprehension result is available yet. This site's detailed route interactions, mobile, keyboard, motion and accessibility were not inspected at runtime in this round.

### 2. HerCode Space — A Solar Tale (Best Use of Storytelling, 2025)

NASA's official announcement confirms the award and says the project combines NASA heliophysics with storytelling and illustrations to teach children how space weather affects daily life. The current candidate story URL [a-solar-tale.netlify.app](https://a-solar-tale.netlify.app/) returned an 813-byte client-side app shell, title “A Solar Tale | A story inspired by NASA data.” It does not server-render any readable story content. The separate [HerCode Studio page](https://studiohercode.com/solar-tale) returned the studio's client-app shell, not observable story screens. A third-party project/community listing attributes the Netlify address to A Solar Tale, but the exact official submission link/version has not been verified. No repository or license was identified in this round.

**Against Lunar.** The relevant transfer is a named audience and a concrete consequence. Lunar already has a delay problem statement, an illustrative diagram and a “How it works” route; this study found no missing story feature. The unresolved check is whether a new visitor can explain why a delay changes sight lines and distinguish visibility from power or communications. Story chapters, motion, mobile, keyboard and reduced motion were not inspected at runtime in this round.

### 3. SpaceGenes+ — Best Use of Science (2025)

NASA confirms the category and describes an interactive dashboard for researchers and mission planners. Its project author's [design write-up](https://medium.com/design-bootcamp/spacegenes-designing-a-tool-to-reveal-hidden-health-risks-in-space-7d46bdc97ef6) labels it a prototype and links the [live dashboard](https://spacegenes-plus.framer.website/). The team page's indexed text (not directly inspected in a browser this round) describes one live OSD-288 mouse-spleen-in-space case, four stressor conditions, a “synergy threshold” formula, heatmap, top-five gene list, tooltip with fold-change and study ID, and PNG export; it explicitly calls other cases conceptual/future. The author says this is a thinking tool, not a final scientific answer. The 442 KB HTML response was not retained or inspected because of the small-read bound. No public source repo or license was found in the checked materials.

**Against Lunar.** Good practice to borrow only as a check: make a metric's inputs, threshold, source and case scope visible near the output, and give the visitor a useful negative/control comparison. Lunar already publishes separate direct-Sun time, current-disc visibility, height and source details; do not collapse these into a composite label. Risk: an attractive model output can overstate clinical or scientific certainty. Verify the app labels its one live case and prototype boundary, and verify any interactive calculation independently before describing it as validated. UI controls, output export, motion, mobile, keyboard and reduced motion remain untested.

### 4. PureFlow — Best Mission Concept (2025)

NASA confirms the award and describes a 3D habitat-design and systems-engineering concept that tests space-weather threats. Its [GitHub repository](https://github.com/larasdiniz/PureFlow-2025) metadata names the GitHub Pages deployment [Space Habitat Designer](https://larasdiniz.github.io/PureFlow-2025/src/public/html/home/home.html). The public repository has a 174-byte README, 20 tree entries, an HTML-only GitHub language report, no `package.json`, and no repository `license` metadata or root LICENSE in the observed tree. The published page loads Tailwind and Lucide from CDNs. No repository was cloned, installed or run.

**Static screen/route ledger (content and source only; no UI interaction was performed).** Home says the product is for Moon/Mars mission layouts and has a single “Start Designing” button to `forms/index.html`. The form page contains crew size 1–50, duration slider and presets, destination cards, propulsion, habitat strategy, material and optional storm-shelter/wall choices; it provides visible cost-analysis fields and a “Generate Mission Profile” button. The source defaults to 4 crew, 365 days and Mars, updates labels and cost cells on input, and writes a profile to browser `localStorage` before routing to `technical-analysis.html`. This is the implementation as authored, not a verified engineering/cost model.

The analysis screen shell says “Loading mission profile...” and includes destination/material/architecture sections, DONKI/CME/FLR/SEP status, a “Risk Analysis & Recommendations” section, Edit and Continue. Briefing screen says “Final Mission Briefing,” offers Back, Start Simulation and New Mission, and routes into the designer. The designer HTML provides 3D/2D/Realistic view labels, interior/exterior layout modes, level assembly, drag-and-drop areas, save/load/download JSON, and keyboard/mouse instructions (W/S/E/Q/Del, left drag to rotate, right drag to pan, scroll to zoom). Its import map declares Three.js 0.157.0 and addons; the source references WebGL. Those instructions and controls were not executed or accessibility-tested. Tailwind, Lucide, an es-module-shims helper and Inter font are loaded from external CDNs on the inspected pages; package/asset license status remains unverified.

**Concrete route gap.** The briefing's static JavaScript navigates to `./export-share.html` and calls it ready to use. A GET to that source-derived path returns the GitHub Pages 404 page; the checked repository tree contains only `briefing.html`, `index.html`, and `technical-analysis.html` under `forms/`, with no `export-share.html`. This is a current published-path mismatch, not a claim about another branch or any unpublished implementation.

**Against Lunar.** The best fit is the form's direct input-to-updated-output pattern and a single scenario that is easy to repeat. Lunar already preserves location, arrival, duration and observer height into comparison, includes a derived report/PDF, and explicitly documents visibility limits; no new builder, cost score or survival model is warranted. Risk: PureFlow labels cost calculations and standards as “NASA”/real without an evidence reference beside each figure, and its GET-only analysis page does not establish live DONKI behavior. Transfer only explicit inputs and a traceable outcome. Verify the output changes from each input, its method/source, export path, and 2D/keyboard alternative before using it as a design precedent.
